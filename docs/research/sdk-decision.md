# ThingsBoard PE Mobile SDK Decision & Screen/Widget Gap Analysis

> **Scope:** Grounded technical trade-off analysis for API/WebSocket integration and complete UI/UX gap matrix for `thingsboard_democloud_app` (`Dart ^3.7.0`, `dio ^5.8.0+1`, `hooks_riverpod ^2.6.1`, `go_router ^17.0.0`).
> **Inputs Inspected:** `pubspec.yaml`, `lib/main.dart`, `lib/config/`, `lib/constants/`, `lib/core/auth/`, `lib/core/mock/mock_data.dart`, `lib/modules/`, `lib/widgets/`, `lib/utils/`, `assets/`, `android/`, and `docs/research/thingsboard-pe-api.md`.

## 1. SDK & API Layer Trade-Off Analysis

### 1.1 Candidate Options

| Criterion | Option A: `thingsboard_pe_client: ^4.4.1` + Riverpod wrappers | Option B: Custom `Dio` + `web_socket_channel` + Lightweight Models | Option C (Recommended): Typed `Dio` Facade (`TbApiClient`) + `TbWebSocketService` + OpenAPI-Aligned Domain Models |
| :--- | :--- | :--- | :--- |
| **Core Transport** | `thingsboard_pe_client` (`dio ^5.7.0`, `built_value`, `one_of`, `web_socket_channel`) | Existing `dioClientProvider` (`dio ^5.8.0+1`) + `web_socket_channel` | Existing `dio ^5.8.0+1` wrapped in `TbApiClient` + `QueuedInterceptor` + `TbWebSocketService` (`web_socket_channel`) |
| **`thingsboard.democloud.xyz` Compatibility** | **Risky.** Targets PE `>= 4.4.0`; `TelemetryControllerApi` uses `/values/timeseries/history`, which 404s on pre-4.4 servers. Startup helpers may expect `/api/noauth/mobile` (which returns `404` on `democloud.xyz`). | **High.** Explicit per-endpoint fallback (`/values/timeseries/history` -> `/values/timeseries?startTs=...`, `404` treated as feature-unavailable). | **High.** Explicit version-resilient endpoints & graceful `404` degradation on `/api/noauth/mobile`, `/api/noauth/whiteLabel/*`, and `/v3/api-docs`. |
| **Model Ergonomics & Boilerplate** | **Heavy.** Auto-generated `built_value` + `BuiltList` + `OneOf` builders; barrel export collides on `LoginRequest`, `EntityId`, `EntityType` (requires `hide`/`show`). | **Light.** Plain `const` immutable Dart classes with `fromJson`/`copyWith`. | **Light.** Plain `const` immutable Dart domain models (`fromJson`/`copyWith`) aligned directly with `docs/research/thingsboard-pe-api.md` schemas. |
| **`Mock*` Model Migration (`mock_data.dart`)** | **High friction.** Must either rewrite every widget to `built_value` builders or maintain a full `built_value <-> domain` mapping layer. | **Direct.** `MockDashboard`, `MockAlarm`, `MockDevice`, etc. evolve 1:1 into domain models (`DashboardItem`, `AlarmItem`, `DeviceItem`). | **Direct.** Existing `Mock*` types graduate cleanly into shared domain models used identically by Live REST/WS and Demo repositories. |
| **Demo / Offline Mode Toggling** | **Awkward.** Constructing fake `built_value` `BuiltList`/`JsonObject` instances for offline fixtures is verbose and brittle. | **Seamless.** Repository interfaces (`AlarmRepository`, `DeviceRepository`, etc.) swap cleanly between `Rest*Repository` and `Demo*Repository` via Riverpod provider override/flag. | **Seamless.** Single `demoModeProvider` switches repository bindings without changing a single widget or provider consumer. |
| **Unit Testability (`Dio` mocking)** | **Moderate.** Must satisfy `ThingsboardClient` internal `Dio`, `built_value` `standardSerializers`, and token storage hooks in tests. | **Excellent.** Pure `Dio` with `HttpClientAdapter` stubs returning plain JSON fixtures + unit-testable `QueuedInterceptor` refresh lock. | **Excellent.** Deterministic `HttpClientAdapter` mock adapter tests for every controller + `StreamController` fake channel tests for `TbWebSocketService`. |
| **Maintenance Surface** | **Minimal for REST.** 745 generated endpoints, though app only uses ~35–40 endpoints. | **Moderate.** Hand-written DTOs/controllers for the ~35–40 endpoints the app actually uses. | **Balanced.** Thin, modular per-domain controllers (`lib/core/api/controllers/`) + shared `PageData<T>` & `ThingsboardError` parser; zero `built_value` codegen. |

### 1.2 Why `thingsboard_pe_client: ^4.4.1` Alone Is Not the Best Fit Here
1. **Verified `thingsboard.democloud.xyz` Behavior:** As verified in `docs/research/thingsboard-pe-api.md` (§1.2), `thingsboard.democloud.xyz` returns `200 OK` on `/api/noauth/userPasswordPolicy` and `POST /api/noauth/oauth2Clients`, but returns **`404 Not Found`** on `/api/noauth/mobile`, `/api/noauth/whiteLabel/loginWhiteLabelParams`, and `/v3/api-docs`. A rigid 4.4.1 client assuming PE 4.4.1 PaaS endpoints (`/values/timeseries/history`, `/api/noauth/mobile`) risks runtime `404` failures unless wrapped in custom fallback logic anyway.
2. **Existing Codebase Alignment:** `pubspec.yaml` already depends on `dio: ^5.8.0+1`, `hooks_riverpod: ^2.6.1`, and `go_router: ^17.0.0`, and `lib/core/auth/login/provider/auth_provider.dart` already declares `dioClientProvider`. Meanwhile `lib/core/mock/mock_data.dart` already models all 10 domain concepts (`MockDashboard`, `MockAlarm`, `MockAlarmComment`, `MockDeviceProfile`, `MockDevice`, `MockCustomer`, `MockAsset`, `MockAuditLog`, `MockNotificationItem`, `MockUserProfile`) as plain immutable Dart classes.
3. **Dual-Mode Requirement (Live PE + Demo/Offline):** Because the app must work both against live ThingsBoard PE servers (`thingsboard.democloud.xyz` or custom host) and in instant Demo/Offline mode (when unauthenticated/offline or testing without credentials), sharing **one** lightweight immutable domain model layer across both `Rest*Repository` and `Demo*Repository` eliminates double-mapping and `built_value` friction.

### 1.3 Final Recommendation: **Option C — Lightweight Typed `Dio` Facade (`TbApiClient`) + Dedicated `TbWebSocketService` + Plain Immutable Domain Models**

- **Do NOT add `thingsboard_pe_client` as a runtime dependency.** Instead, treat `docs/research/thingsboard-pe-api.md` (derived from the PE `4.4.1PAAS` OpenAPI 3.1.0 spec) as the strict API contract for our typed `Dio` controllers.
- **Add only minimal, high-leverage runtime packages:**
  - `flutter_secure_storage` (persist JWT access/refresh tokens, server URL, demo-mode flag)
  - `jwt_decoder` (inspect JWT `exp`, `userId`, `authority`, `tenantId`, `customerId` locally without round-trips)
  - `web_socket_channel` (single shared `wss://<host>/api/ws` multiplexer for `ENTITY_DATA`, `ENTITY_COUNT`, `ALARM_DATA`, `ALARM_COUNT`, `NOTIFICATIONS`, `NOTIFICATIONS_COUNT`, and v1 `ATTRIBUTES`/`TIMESERIES`)
  - `mobile_scanner` (real camera QR login & device claiming on `/qrCodeScan`)
  - `url_launcher` or `webview_flutter` (for OAuth2 external browser/CustomTabs callback & optional embedded full ThingsBoard dashboards)
- **Architecture Summary:**
  - `TbApiClient`: wraps `Dio` with `X-Authorization: Bearer <jwt>` injection, single-flight `QueuedInterceptor` token refresh (`POST /api/auth/token` on `401` + `errorCode == 11`), normalized `ThingsboardException` (`ThingsboardErrorCode` table), and dynamic `baseUrl` switching.
  - `TbWebSocketService`: single `keepAlive` Riverpod service managing `wss://<host>/api/ws`, `authCmd`, 90s keepalive ping, `cmdId` subscription multiplexing, `AppLifecycleState.resumed` reconnect with exponential backoff, and automatic unsubscribe on provider disposal.
  - **Repository & Demo Toggle:** Abstract repository interfaces per domain (`Auth`, `Dashboard`, `Alarm`, `Device`, `Asset`, `Customer`, `Telemetry`, `Rpc`, `Notification`, `AuditLog`, `User`) with `Rest*` and `Demo*` implementations switched by `isDemoModeProvider`.
  - **Pre-4.4 Compatibility Guard:** `TelemetryRepository` calls `/values/timeseries/history` for range queries and falls back automatically to `/values/timeseries?startTs=...&endTs=...` on `404`/`400`; optional `/api/noauth/mobile` and `/api/whiteLabel/*` calls catch `404` and return `null` cleanly.

## 3. Priority Cleanup & Architectural Action Items
1. **Unblock Routing First:** Wire `NavigationPage` via `StatefulShellRoute.indexedStack` in `lib/config/routes/router.dart`, add auth redirect guard, and retire `HomePlaceholderPage`.
2. **Unify Theme & Brand Tokens:** Enable `useMaterial3: true` in `tb_theme.dart`, align `TbThemeUtils` with `AppColors` (`primaryBlue` CE/PE palette + semantic status tokens), add dark `ColorScheme`, and remove hardcoded hex colors from `devices_list_page.dart` / `devices_main_page.dart`.
3. **Establish `TbIcons` + Minimal-Text Widgets:** Build `TbIcons` and shared `StatusBadge`, `MetricPill`, `EntityCard`, `ShimmerList` components before implementing `More`, `Customers`, `Assets`, `AuditLogs`, `Notifications`, and `Profile`.
4. **Migrate `mock_data.dart` to `Core Domain Models + Repository Interfaces`:** Introduce `TbApiClient`, `TbWebSocketService`, and `Demo*` vs `Rest*` repositories so every screen works identically in Demo Mode and against live `https://thingsboard.democloud.xyz/`.
5. **Fix `android/app/src/main/AndroidManifest.xml`:** Add `<uses-permission android:name="android.permission.INTERNET" />`, `CAMERA` permission, OAuth2 callback `<intent-filter>`, and apply `assets/branding/` launcher/splash assets.
